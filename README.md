# Wordframe

Тренажёр английской лексики для русскоязычных учащихся. Выберите уровень A1–C1 или подборку «Casualties Unknown» и при желании отфильтруйте карточки по части речи. Для фразовых глаголов есть своя вкладка. Нажмите на подчёркнутое слово в примере, чтобы увидеть его значение.

В тренажёре три режима. В **EN → RU** и **RU → EN** нужно выбрать перевод слова или выражения, а в режиме **Пропуски** — ввести нужную английскую форму. Подборки и ответы сохраняются отдельно для каждого режима.

Во вкладке **Грамматика** собраны правила и двуязычные примеры по временам, условным предложениям и другим темам. Из правила можно сразу перейти к упражнениям по теме. Материалы хранятся в `dist/grammar.js`.

## Генерация примеров

В локальной вкладке «Настройки» можно выбрать бесплатный маршрут `deepseek-v4-flash-0731:free` или платные модели `claude-haiku-5.5` и `gpt-6.1-terra`. Для бесплатного маршрута нужно привязать Telegram в PlusVibe.

В тренажёре переключатель «Готовые / С ИИ» выбирает источник заданий. В режиме ИИ можно создать от 1 до 20 новых словарных карточек или отдельное задание с пропуском. У словарных карточек есть варианты для EN → RU и RU → EN, проверка ответа и перевод слов по нажатию. Слова и фразы сверяются с основной базой и ранее сгенерированными пачками в этом браузере. Для Haiku сервер использует Messages API с параметром `thinking: { type: 'disabled' }`.

Для локального запуска выполните `node server.cjs` и откройте `http://127.0.0.1:8080/#settings`. Вставьте ключ PlusVibe в поле «Ключ PlusVibe». Ключ и выбранная модель остаются в памяти сервера до перезапуска. Кнопка «Сохранить и проверить обе» делает один пробный запрос к каждой модели. При желании можно задать `PLUSVIBE_API_KEY` и `PLUSVIBE_MODEL` в локальном файле `.env`, который Git игнорирует, и запустить `node --env-file=.env server.cjs`.

Для доступа с телефона через интернет сервер можно запустить на своём компьютере за HTTPS-прокси (например, Caddy). Сам Node-сервер оставьте на `127.0.0.1`: наружу открывайте только HTTPS-прокси. Нужен домен, указывающий на белый IP, и доступные извне порты для получения сертификата. Не открывайте Node-сервер напрямую по HTTP: токен и API-запросы могут быть перехвачены.

Создайте токен командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"`. Храните его как пароль. Укажите в локальном `.env` (файл исключён из Git):

```dotenv
WORDFRAME_TOKEN=созданный_токен
PLUSVIBE_API_KEY=ключ_PlusVibe
PLUSVIBE_MODEL=claude-haiku-5.5
PORT=8084
```

Запустите `node --env-file=.env server.cjs`. Для Caddy используйте конфигурацию `ваш-домен { reverse_proxy 127.0.0.1:8084 }` и настройте HTTPS по документации Caddy. На телефоне откройте HTTPS-адрес, введите имя пользователя `wordframe`, а вместо пароля — токен. Локальные настройки через браузер в защищённом режиме отключены; ключ и модель задаются в `.env` и применяются после перезапуска. Старый параметр `WORDFRAME_PASSWORD` также поддерживается, но `WORDFRAME_TOKEN` имеет приоритет. Прогресс хранится отдельно для каждого адреса сайта.

## Аккаунты и база данных

Для аккаунтов на Node.js 24 укажите `WORDFRAME_ACCOUNTS=1`, общий `PLUSVIBE_API_KEY` и случайный 32-байтовый ключ `WORDFRAME_ENCRYPTION_KEY` (64 шестнадцатеричных символа) в локальном `.env`. Запустите `node --env-file=.env server.cjs` за HTTPS-прокси. Для общего ключа каждому аккаунту доступно до 500 запрошенных карточек за пять часов. Лимит списывается при отправке запроса, в том числе если модель вернула некорректный ответ. Регистрация открыта: лимит на аккаунт не защищает от создания новых аккаунтов, поэтому дополнительно установите ограничение расходов у провайдера. Пользователь может выбрать свой ключ без общей квоты; личные ключи хранятся в SQLite зашифрованными AES-256-GCM. Сохраняйте резервные копии и базы, и `WORDFRAME_ENCRYPTION_KEY` отдельно в защищённом месте: потеря ключа шифрования сделает личные ключи нечитаемыми. Администратор сервера, имеющий доступ к конфигурации и базе, технически может их расшифровать. Настройте прокси так, чтобы он перезаписывал `X-Wordframe-IP` фактическим адресом клиента; сам Node-сервер должен слушать только localhost.

По умолчанию SQLite создаёт базу `.env.wordframe.sqlite` в рабочем каталоге; можно указать путь переменной `WORDFRAME_DB`. База и её WAL должны оставаться закрытыми; не храните их в опубликованном каталоге и не добавляйте в Git. Делайте резервные копии базы штатными средствами SQLite. На устройстве с прежним прогрессом при первом входе можно согласиться на перенос в новый аккаунт. Сохранение в браузере остаётся запасной копией при потере связи. Одновременное редактирование на разных устройствах не объединяется автоматически — последняя запись заменяет предыдущую.

## Запуск

Откройте `dist/index.html` в браузере. Для статического хостинга используйте папку `dist`. Прогресс хранится в браузере. Для озвучки используются установленные в браузере голоса.

## Лексика

Дополнительные примеры лежат в `vocabulary-a2.txt`, `vocabulary-b1.txt` и `vocabulary-b2.txt`, `vocabulary-c1.txt`. Строки содержат часть речи (`n`, `v`, `a` или `p` для фразовых глаголов), предложение с пометками и перевод. Конструкция `[слово=перевод]` задаёт изучаемое слово. Запись `word=перевод` задаёт значение вспомогательного слова в этой фразе. Текст хранится в UTF-8.

Лексика «Casualties Unknown» хранится в `vocabulary-casualties-unknown.txt` и также входит в общие уровни A2–B2. Каждая карточка содержит перефразированную игровую ситуацию из английской локализации и простой пример с тем же словом или выражением. В тренажёре между примерами можно переключаться, а в сохранённой карточке словаря видны оба примера. В исходном файле поля разделяются символом `|`, изучаемое выражение выделяется квадратными скобками. Последнее поле задаёт ориентировочный уровень карточки.

Лексика про выживание и снаряжение лежит в `vocabulary-casualties-unknown-survival.txt` в том же формате. Переводы слов из игровых примеров и уточнения к отдельным фразам лежат в `vocabulary-casualties-unknown-glosses.txt`. После изменения базы выполните `node compile-vocabulary.cjs`. Скомпилированные карточки находятся в `dist/words.js`. GitHub Pages публикует папку `docs`, поэтому перед отправкой изменений скопируйте обновлённые файлы из `dist` в `docs`.
